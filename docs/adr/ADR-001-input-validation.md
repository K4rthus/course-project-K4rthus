# ADR-001: Валидация ввода и обработка файлов

Дата: 2025-03-11
Статус: Accepted

## Context
Сервис ящика предложений обрабатывает пользовательский ввод через US-001 (создание предложений) и US-002 (фильтрация). 
По данным STRIDE анализа выявлены риски:
- **R6**: SQL инъекции в фильтрацию (F9)
- **R14**: XSS атаки через пользовательский ввод (U Клиент)
- **R3**: Утечка PII через данные предложений (F3)

NFR-04 требует маскирования конфиденциальных данных, NFR-09 - контроль уязвимостей.

## Decision
Применяем многоуровневую валидацию, соответствующую выявленным рискам:

1. **SQL инъекции**: Используем SQLAlchemy ORM с параметризованными запросами для фильтрации по статусу (US-002)
2. **XSS защита**: Санитизация HTML в title/text (макс. 100/2000 chars) с экранированием специальных символов
3. **Валидация файлов**:
   - Максимальный размер: 5MB (соответствует NFR-01 по производительности)
   - Разрешенные MIME: image/png, image/jpeg, application/pdf
   - Проверка magic bytes + расширение файла
   - Имена файлов как UUID для предотвращения path traversal

## Alternatives
1. **Библиотека marshmallow** - более сложная валидация, но избыточная для текущих потребностей
2. **pydantic с кастомными валидаторами** - уже используется, оптимально для FastAPI
3. **Сторонний сервис валидации** - излишняя сложность для MVP

Выбран pydantic + кастомная бизнес-логика как наиболее соответствующий стеку.

## Consequences
**Плюсы:**
- Mitigates риски R6, R14, R3 из RISKS.md
- Соответствует NFR-04, NFR-09, NFR-01
- Минимальное влияние на p95 времени ответа

**Минусы:**
- +15ms на валидацию файлов при p95
- Ограничение типов файлов для пользователей

## Security Impact
**Влияние на безопасность:**
- Снижение риска R6 с 10 до 2 (ORM предотвращает SQL инъекции)
- Снижение риска R14 с 12 до 4 (санитизация ввода)
- Соответствие NFR-04 через маскирование в логах

**Меры мониторинга:**
- Логирование попыток обхода валидации
- Метрики количества отклоненных файлов по типам

## Rollout Plan
1. **Фаза 1**: Добавить feature-flag `ENHANCED_VALIDATION`
2. **Фаза 2**: Развернуть в staging с тестовой нагрузкой 50 RPS
3. **Фаза 3**: Canary rollout на 10% production трафика
4. **Фаза 4**: Полное включение после 48ч стабильной работы

**DoD (Definition of Done):**
- [ ] Все тесты проходят (unit/integration/security)
- [ ] Нагрузочные тесты показывают p95 < 200ms
- [ ] Мониторинг не показывает ложных срабатываний
- [ ] Документация API обновлена
