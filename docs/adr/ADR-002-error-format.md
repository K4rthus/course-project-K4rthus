# ADR-002: Стандартизация формата ошибок по RFC 7807

Дата: 2025-03-11
Статус: Accepted

## Context
Текущая система возвращает ошибки в произвольном формате, что противоречит:
- **NFR-04**: Конфиденциальность данных - риски R3 и R8 (утечка через логи ошибок)
- **NFR-10**: Аудит действий - необходимость корреляции ошибок
- **R8** из RISKS.md: Утечка данных через логи ошибок

STRIDE анализ выявил угрозы Information Disclosure (I) через логи ошибок.

## Decision
Принимаем стандарт RFC 7807 (Problem Details for HTTP APIs) с учетом требований безопасности. 1ю
1. **Структура ошибок**:
```json
   {
     "type": "/errors/validation",
     "title": "Validation Error",
     "status": 422,
     "detail": "One or more validation errors occurred",
     "correlation_id": "uuid-v4",
     "instance": "/suggestions"
   }
```
2. **Безопасность**: Маскирование stack trace в production, отдельные типы для клиентских/серверных ошибок
3. **Аудит**: correlation_id для трассировки через системы (соответствует NFR-10)
4. **Конфиденциальность**: Детали ошибок не содержат PII (соответствует NFR-04)

## Alternatives
1. **Кастомный JSON формат** - большая гибкость, но отсутствие стандартизации
2. **GraphQL ошибки** - не применимо к REST API
3. **Оставить как есть** - неприемлемо из-за рисков R3/R8

Выбран RFC 7807 как индустриальный стандарт с готовыми клиентскими библиотеками.

## Consequences
**Плюсы:**
- Mitigates риски R3, R8 (снижение с 12/9 до 4/3)
- Соответствует NFR-04, NFR-10
- Упрощение клиентской обработки ошибок

**Минусы:**
- Увеличение размера JSON ответов на 20-30%
- Необходимость обновления клиентов

## Security Impact
**Влияние на безопасность:**
- Предотвращение утечки системной информации через ошибки
- Возможность трассировки инцидентов через correlation_id
- Соответствие требованиям аудита (NFR-10)

**Компромиссы:**
- Баланс между детализацией для отладки и безопасностью
- Разделение error types для development/production

## Rollout Plan
1. **Фаза 1**: Реализовать middleware с feature-flag `RFC7807_ERRORS`
2. **Фаза 2**: A/B тестирование на 20% трафика в staging
3. **Фаза 3**: Постепенный rollout с мониторингом клиентских ошибок
4. **Фаза 4**: Полное включение + обновление документации

**DoD:**
- [ ] Все эндпоинты возвращают RFC 7807 ошибки
- [ ] correlation_id присутствует в 100% ошибок
- [ ] Логи содержат correlation_id для трассировки
- [ ] Клиенты успешно обрабатывают новый формат
