# BDD-сценарии для Suggestion Box

## Feature: Производительность создания предложений

```gherkin
Scenario: p95 времени создания предложения в пределах нормы
  Given сервис развернут на staging среде
  And настроен нагрузочный тест на 100 RPS
  When запускается 10-минутный нагрузочный тест на endpoint POST /suggestions
  Then p95 времени ответа должен быть ≤ 200 ms
  And процент ошибок должен быть ≤ 1%

Scenario: Обработка пиковой нагрузки
  Given сервис работает в нормальном режиме
  When поступает всплеск нагрузки до 200 RPS на 2 минуты
  Then сервис должен обработать все запросы без падения
  And p99 времени ответа должен быть ≤ 500 ms
```

## Feature: Безопасность аутентификации
```gherkin
Scenario: Защита от brute-force атак
  Given пользователь с IP 192.168.1.100
  When совершено 5 неудачных попыток аутентификации в течение 60 секунд
  Then следующие попытки с этого IP блокируются на 5 минут
  And в логи записывается событие блокировки

Scenario: Успешная аутентификация после блокировки
  Given IP адрес был заблокирован из-за превышения лимита попыток
  When прошло 5 минут с момента блокировки
  Then аутентификация с этого IP снова разрешена
  And счетчик неудачных попыток сбрасывается
```

## Feature: Конфиденциальность данных в логах

```gherkin
Scenario: Маскирование email в логах
  Given пользователь с email "user@example.com"
  When происходит ошибка аутентификации
  Then в логах email отображается как "u***@e***.com"
  And оригинальный email нигде не фигурирует в открытом виде

Scenario: Логирование без PII
  Given создается новое предложение с текстом "Мой секретный план"
  When предложение сохраняется в системе
  Then в application логах не фигурирует содержимое предложения
  And в audit логах сохраняется только факт создания с user_id
```

## Feature: Целостность модерации

```gherkin
Scenario: Только модератор может менять статусы
  Given обычный пользователь без прав модератора
  When пользователь пытается изменить статус предложения через PATCH /suggestions/{id}
  Then возвращается ошибка 403 Forbidden
  And статус предложения не изменяется

Scenario: Аудит действий модератора
  Given модератор с правами изменения статусов
  When модератор изменяет статус предложения с "pending" на "approved"
  Then действие записывается в audit log с timestamp и user_id
  And старый и новый статус сохраняются в истории изменений
```

## Feature: Надежность базы данных

```gherkin
Scenario: Восстановление после сбоя БД
  Given работает основная база данных
  When происходит сбой основной БД
  Then система автоматически переключается на replica в течение 30 секунд
  And потеря данных не превышает 5 минут изменений
  And сервис продолжает работать в режиме read-only
```
